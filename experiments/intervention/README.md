# Intervention: does the auditor's advice change what the agent does next?

**What is measured.** For failures the live auditor detected in the replay, whether injecting its advice
makes the original agent model correct (or, for early warnings, avoid) the failure in its next turn,
compared with no message, a generic reminder, and plausible but wrong advice (paper: "Behavioral
correction via auditor intervention" and the appendix "Evaluation Details").

**Protocol.** Items come from the live-auditor scores (`supervisor/runs/test_sonnet_pi/scores.json`): a
detected failure, cut at the last step the auditor had seen when it first flagged it (*prevention* if the
cut precedes the annotated onset, else *correction*).  The agent's conversation is rebuilt from the
normalized trajectory (task instruction, visible text, tool calls, tool outputs capped at 30k characters,
no reasoning), up to the first tool result at or after the cut; the advice is appended to that tool result
as `[Supervisor Advice]`.  The original model (OpenRouter Messages API) samples its next turn at
temperature 1 with up to 12k tokens; turns without visible text or tool call are resampled.  Conditions:
`none`, `specific` (the auditor's advice), `generic` ("Before continuing, double-check your method and
whether your results support your claims."), `wrong` (written by Claude Sonnet 5.5 to sound expert but
miss the flaw; all were read before use).  GPT-5.6 labels each turn corrects / acknowledges / no without
seeing the condition, and for `wrong` whether the agent follows / questions / ignores the message.

Two rounds, two samples per condition:
* `main`: two failures per agent model (7 models, 14 failures, 13 invalidating), all four conditions.
* `focus3`: every detected (non-minor) failure of Opus 4.8, GLM-5.2 and GPT-5-mini (35 failures: 15
  correction, 20 prevention, 10 invalidating), conditions none / specific / wrong.  The 6 failures shared
  with `main` were copied from it (`seed` phase), including their `generic` samples (12).

**Inputs** (`<data-dir>/intervention/`): `instruction_template_tail.md` and `runs/{main,focus3}/`
(`items.json`, `wrong/`, `samples/`, `judged/`).  The rebuilt contexts (`prefix/`) are not shipped; the
`prep` phase rebuilds them identically from AutoResearchEval.

## (b) Re-run the models

```bash
export OPENROUTER_API_KEY=...
bash intervention/reproduce.sh rerun
```

which runs, for each round, the phases (each reads the previous phase's files, so they can be run and
inspected one at a time):

```bash
python -m intervention.run_intervention select --per-model 2 --out-dir runs/intervention/main   # free
python -m intervention.run_intervention prep   --out-dir runs/intervention/main   # contexts (free) + wrong advice (~$0.1)
python -m intervention.run_intervention probe  --out-dir runs/intervention/main   # one short call per model (~$0.06)
python -m intervention.run_intervention run --n 2 --out-dir runs/intervention/main   # ~$3.3
python -m intervention.run_intervention judge  --out-dir runs/intervention/main   # ~$0.7
python -m intervention.run_intervention summary --out-dir runs/intervention/main

python -m intervention.run_intervention select --models glm-5.2 gpt-5-mini opus-4.8 --all --out-dir runs/intervention/focus3
python -m intervention.run_intervention seed --from runs/intervention/main --out-dir runs/intervention/focus3
python -m intervention.run_intervention prep --out-dir runs/intervention/focus3
python -m intervention.run_intervention run --n 2 --conditions none specific wrong --out-dir runs/intervention/focus3   # ~$10
python -m intervention.run_intervention judge --out-dir runs/intervention/focus3   # ~$2
python -m intervention.run_intervention summary --out-dir runs/intervention/focus3
```

`select` reproduces the released `items.json` of both rounds exactly; `--budget` (default $30) stops
sampling past that spend.  Needs AutoResearchEval.  The wrong advice is regenerated by a model and should
be read before use, as in the paper; to reuse the released wrong advice instead, copy
`data/intervention/runs/<round>/wrong/` into the new run directory before `prep`.
